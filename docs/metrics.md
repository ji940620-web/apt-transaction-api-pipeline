# 지표 정의

이 문서는 `sql/` 아래 뷰·테이블이 만드는 컬럼과 지표의 정의를 모은 것입니다.
값이 어떻게 계산되는지는 각 SQL 파일이 기준이며, 문서와 다르면 SQL을 따릅니다.

공통 규칙

- 금액 단위: **만원** (매매가, 보증금, 월세 모두)
- 면적: **전용면적** (`excluUseAr`, ㎡). 평 = ㎡ / 3.3058
- 중위값: `APPROX_QUANTILES(x, 100)[OFFSET(50)]` → **근사 중위값**
- 당월 제외: `v_sales`, `v_rents`는 **이번 달(Asia/Seoul) 거래를 제외**합니다. 진행 중인 달은 건수가 계속 바뀌기 때문입니다.
- 잠정치: 신고 기한(계약 후 30일) 때문에 최근 1~2개월은 재수집 시 증가합니다.

## 핵심 지표 요약

| 지표 | 정의 | 계산 위치 | 해석 시 주의 |
|---|---|---|---|
| **중위 거래가** | 매매가의 50번째 백분위수 (만원) | `m_sido_monthly.median_price_clean`, Looker `MEDIAN(amount)` | 평균 대신 중위값 사용 (고가 거래에 덜 흔들림). 평형 구성 영향을 받으므로 추이는 평당가로 봄 |
| **중위 평당가** | `price / (전용㎡ / 3.3058)`의 중위값 (만원) | `m_sido_monthly.median_price_per_py` | 전용면적 기준 (공급면적 기준 시세보다 높게 보임) |
| **일괄 거래 제외** | `is_bulk = FALSE`인 매매만 집계 | `v_sales_clean.is_bulk` | 같은 단지·날짜·가격 10건 이상 = 일괄. 기준값은 임의 |
| **잠정 표시** | 집계 시점 기준 **최근 2개 완료 월**은 잠정치로 표시 | 대시보드 표시 규칙 (SQL 컬럼 아님) | 재수집 시 건수가 늘어남. 서울 2026-10: 재수집 1회에 +18% |
| **월말/월초 비율** | `avg_d21_end / avg_d01_10` | `m_sido_pace` | 신고 완료 월 ≈ 0.88 (서울). 크게 낮으면 신고 지연 |
| **전세가율 (지역)** | 전세 보증금 중위값 / 매매가 중위값 × 100 | `m_region_monthly.jeonse_ratio_pct` | 거래 구성 차이로 100% 초과가 흔함 (11.5%). `enough_sample`(각 30건 이상)만 사용 |
| **전세가율 (단지·면적)** | 같은 단지·5㎡ 면적대의 전세 중위값 / 매매 중위값 × 100 | `m_complex_ratio.jeonse_ratio_pct` | 매매·전세 각 3건 이상만. 100% 초과 0.9% |
| **전월 대비 증감** | 이번 달 건수 / 전월 건수 − 1 | `sql/checks/monthly_count_mom.sql` | 최근 월은 잠정치라 감소로 과장됨 |

## 1. 기본 컬럼 (`v_sales`, `v_rents`)

| 컬럼 | 정의 | 비고 |
|---|---|---|
| `region_name` | 시군구 이름 (예: `서울특별시 종로구`) | 법정동코드 파일 기준 |
| `complex_key` | `lawd_cd \| umd_nm \| apt_nm` | 단지 식별자. 같은 이름이 다른 동에 있으면 구분됨 |
| `deal_date` | 계약일 | |
| `deal_month` | 계약월 1일 (DATE) | 집계 기준 월 |
| `price` | 매매가 (만원) | `dealAmount > 0`만 포함 |
| `deposit` | 보증금 (만원) | 전세·월세 공통 |
| `monthly_rent` | 월세 (만원) | 전세는 0 |
| `rent_type` | `monthly_rent = 0` → `전세`, 그 외 `월세` | 수집 단계에서 월세 NULL을 0으로 채움 |
| `area_m2` / `area_py` | 전용면적 ㎡ / 평 (소수 1자리) | `excluUseAr > 0`만 포함 |
| `price_per_py` | `price / (area_m2 / 3.3058)` | 전용면적 기준 평당가 (만원) |
| `building_age` | `dealYear - buildYear` | 매매만 |

## 2. 일괄 거래 (`v_sales_clean`)

| 컬럼 | 정의 |
|---|---|
| `is_bulk` | 같은 `complex_key` + `deal_date` + `price` 조합이 **10건 이상**이면 TRUE |

- 목적: 법인 간 일괄 직거래 같은 비정상 신고가 지역 중위가를 왜곡하는 것을 막기 위함
  (2026-10-08 동대문구 한 단지 313건 → 동대문구 10월 중위가 24,488 vs 제외 시 94,000만원)
- 삭제하지 않고 표시만 합니다. 사용할 때 `WHERE NOT is_bulk`.
- 10건 기준은 임의값입니다. 전세·월세에는 적용하지 않습니다.

## 3. 지역 월별 (`m_region_monthly`)

단위: 시군구 × 월, 기간 2025-02 이후 (2025-01은 수집 시작월이라 부분 데이터)

| 컬럼 | 정의 |
|---|---|
| `sale_n`, `sale_median` | 매매 건수, 매매가 중위값 (일괄 거래 **포함**) |
| `jeonse_n`, `jeonse_median` | 전세 건수, 전세 보증금 중위값 |
| `jeonse_ratio_pct` | `jeonse_median / sale_median × 100` (소수 1자리) |
| `enough_sample` | `sale_n ≥ 30 AND jeonse_n ≥ 30` |

> 주의: 지역 단위 전세가율은 매매와 전세의 **거래 구성(단지·면적)이 달라** 100%를 크게 넘는 값이 나옵니다
> (최대 1,226%). 단지 비교에는 아래 `m_complex_ratio`를 쓰세요.

## 4. 단지·면적 전세가율 (`m_complex_ratio`)

단위: 시군구 × 단지 × 면적대, 기간: **최근 3개 완료 월**

| 컬럼 | 정의 |
|---|---|
| `area_band` | `ROUND(area_m2 / 5) × 5` → 5㎡ 단위 (반올림) |
| `sale_median`, `jeonse_median` | 같은 단지·면적대의 매매가 / 전세 보증금 중위값 |
| `jeonse_ratio_pct` | `jeonse_median / sale_median × 100` |
| `is_over_100` | 전세가율 100% 초과 여부 (깡통전세 위험 신호) |

- 포함 조건: 매매·전세 모두 **3건 이상**인 단지·면적대만 (inner join)
- 일괄 거래 **포함** (`v_sales` 기준)

## 5. 시도 월별 (`m_sido_monthly`)

단위: 시도 × 월, 기간 2025-02 이후. 시도 = `region_name`의 첫 단어.

| 컬럼 | 정의 |
|---|---|
| `trades_all` | 전체 매매 건수 |
| `trades_clean` | 일괄 거래 제외 건수 |
| `median_price_clean` | 일괄 제외 매매가 중위값 (만원) |
| `median_price_per_py` | 일괄 제외 평당가 중위값 (만원, 정수) |

- 총액 중위가는 평형 구성에 흔들리므로 **추이는 평당가로** 봅니다.
- 시도 단위 중위값도 지역 구성 영향을 받는 참고 지표입니다.

## 6. 월내 거래 속도 (`m_sido_pace`)

신고 지연 점검용. 일괄 거래 제외, 2025-02 이후.

| 컬럼 | 정의 |
|---|---|
| `avg_d01_10` | 1~10일 건수 / 10 |
| `avg_d11_20` | 11~20일 건수 / 10 |
| `avg_d21_end` | 21일~말일 건수 / (그 달 일수 − 20) |

파생 지표 (쿼리에서 계산)

- **월말/월초 비율** = `avg_d21_end / avg_d01_10`
  - 신고가 끝난 월 기준값: 서울 약 **0.88** (2026-06~08)
  - 최근 월이 이보다 크게 낮으면 신고 지연으로 판단 (예: 서울 2026-10 = 0.48 → 재수집 후 0.64)
- **월초 10일 일평균**은 신고 지연 영향을 *상대적으로 덜* 받지만, 재수집 시 증가합니다(서울 10월 +4.4%).
- 일요일·공휴일(추석 등)이 많은 구간은 평균이 낮아질 수 있습니다.

## 8. Looker용 거래 테이블 (`lk_deals`)

1행 = 1거래 (매매·전세·월세 통합). 중위값은 미리 집계하면 지역끼리 다시 합칠 수 없어
거래 단위로 두고 Looker에서 `MEDIAN()`으로 계산합니다. **수집 후 다시 실행**해야 최신이 됩니다.

| 컬럼 | 정의 |
|---|---|
| `deal_type` | `매매` / `전세` / `월세` |
| `sido`, `sigungu`, `dong` | `region_name` 첫 단어 / 나머지 / `umd_nm` |
| `amount` | 매매 = 매매가, 전세·월세 = 보증금 (만원) |
| `monthly_rent` | 월세만 값 있음 |
| `area_band` | `FLOOR(area_m2 / 5) × 5` → 5㎡ 단위 (**내림**) |
| `area_label` | 예: `80~85㎡` |
| `complex_area_key` | `complex_key \| area_band` |
| `amount_per_py` | `amount / (area_m2 / 3.3058)` |
| `amount_band` | 3억 미만 / 3~5억 / 5~7억 / 7~10억 / 10~15억 / 15억 이상 |
| `is_bulk`, `bulk_label` | 매매만 적용, 전세·월세는 항상 FALSE / `일반 거래` |

> 주의: `lk_deals`의 `area_band`는 **내림(FLOOR)**, `m_complex_ratio`·`complex_ratio_summary`는 **반올림(ROUND)** 이라
> 같은 거래가 서로 다른 면적대에 들어갈 수 있습니다. 두 결과를 직접 비교하지 마세요.

| 컬럼 | 정의 |
